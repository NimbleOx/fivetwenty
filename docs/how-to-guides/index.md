# How-to Guides - Problem-Oriented Solutions

## What are How-to Guides?

How-to guides are **problem-oriented** content that provide direct, practical solutions to specific tasks you need to accomplish with FiveTwenty. They assume you know what you want to do and focus on showing you the most efficient way to do it.

## When to Use How-to Guides

**Use how-to guides when you:**

- **Have a specific problem** to solve
- **Know what you want to achieve** but need the steps
- **Want the most direct solution** without extensive explanation
- **Need to get something done** quickly and efficiently
- **Are comfortable** with the basics and need specific guidance

**Don't use how-to guides when you:**

- Want to learn concepts (use [Tutorials](../tutorials/index.md))
- Need API details (use [API Reference](../api-reference/index.md))
- Want to understand why something works (use [Explanations](../explanation/index.md))

## How-to Guide Structure

Each guide follows a consistent, problem-solving structure:

### **Problem Statement**
- Clear description of what you're trying to achieve
- When you might need this solution
- Prerequisites and assumptions

### **Solution Steps**
- Direct, actionable instructions
- Working code examples you can copy
- Alternative approaches when relevant

### **Verification**
- How to confirm the solution worked
- Expected outcomes and success indicators
- Common issues and quick fixes

### **Troubleshooting**
- Common problems and their solutions
- Error messages and what they mean
- When to seek additional help

## Guide Principles

Our how-to guides are designed with these principles:

### **Goal-Oriented**
- Start with your specific objective
- Provide the most direct path to success
- Focus on practical implementation
- Minimize unnecessary explanation

### **Efficiency-Focused**
- Get you to a working solution quickly
- Assume competence with basic concepts
- Provide ready-to-use code examples
- Include performance considerations

### **Practical Solutions**
- Address real-world scenarios
- Include error handling and edge cases
- Consider production requirements
- Account for different deployment contexts

### **Actionable Instructions**
- Step-by-step procedures you can follow
- Clear success criteria for each step
- Concrete examples with actual code
- Multiple solution approaches when helpful
